# 奶睿pro v1.1.5 更新公告

> **一句话**：播放页这版修了那个最烦人的老毛病 —— UP 主信息卡片不再「悬浮」也不再「往上窜」，
> 老老实实跟着标题待在左栏里；多人合作投稿的稿件不再顶一条「创作团队 N 人」横幅；
> 右栏推荐视频的封面大小可以自己调了。

送审包：`bili-elite-1.1.5.zip`（213 KB / 14 个文件 / `manifest.json` 在 zip 根目录）。

---

## 新增 · 右侧推荐视频封面大小

开关在 **设置 → 界面优化 → 播放页优化** 那张卡里，多了一条滑块。

- **默认 320px = 现在的大小**，一个像素都不差。范围 220~400，步长 10。
- 卡片高度不用管 —— 封面自己带 `16:9 附近的固定比例`（`141 / 80`），宽度变了高度自己跟。
  实测 620px 宽的右栏下：320 → 316×179、400 → 395×224、220 → 221×125。
- **只在播放页优化打开时生效**：那个开关关掉时，这条滑块整行变灰、点不动。
- 上限停在 400（试过 420）：1440 那种窄右栏下，文字那侧只剩 124px，标题会被挤成一列单字。

## 变更 · 多人合作投稿（创作团队）

多人稿件（联合投稿）的 UP 面板是 B 站的另一套结构，和单 UP 完全不是一棵树。

- **「创作团队 N 人」那条通栏灰条整条去掉。** 它占掉 44px，头像要等到标题下面 52px 才出现
  （单 UP 是 8px），整块信息区看着就散了；而且它自己是通栏灰底，比头像那一行重得多，
  把「UP 主控件」这个视觉单元切成了两段。
- **多个 UP 主和右侧点赞 / 投币 / 收藏 / 分享那一排回到同一行。** 实测头像中线与操作栏中线
  都是 621，严丝合缝。
- **间距和单 UP 主时逐像素一致**：头像 ↔ 标题 8px、卡片 ↔ 简介卡 10px。
- **折叠能力没有丢。** 原来折叠是靠横幅右边那颗箭头展开的，横幅一藏就没有展开入口，
  成员超过一行会被裁掉。现在整块自然折行，行距 12px。实测把卡片压到 320px 宽：
  5 人折成两行、容器高 180，没裁掉任何一张。
- 宽屏 / 网页全屏 / 全屏下一条都不生效：那三种模式信息区整套交回 B 站，横幅照常显示。

## 变更 · 「N 人正在看」挪到播放数据那一行

- 位置：播放数据那一行（`15万 · 76 · 2026-10-23 20:57:39 · #话题…`）的**最右端**，
  12px 灰色，和播放数据同一条基线。窗口窄、话题标签折行时，它跟着第一行靠右。
- 之前把弹幕发送栏搬进控制栏时，顺手把这块人数藏掉了 —— 滚到评论区就再也看不到。
  现在放回来，不用多占一行。
- 数字还是 B 站自己那一个节点、自己轮询刷新，我们只读文本、不往那块插任何东西
  （那块是 B 站高频重渲染的区域，插节点会让它错位）。

## 变更 · 简介卡

- **与评论之间补 10px 间距。** B 站原本这两块之间一点缝都没有，灰卡的圆角直接贴着
  「评论」那一行的标题，看着像糊成一张。补的数就是「UP 主控件 ↔ 简介卡」那个 10px，
  单 UP / 多人两种稿件都生效。
- **收起态的悬停高亮换成暖白** `#FFF7F0`（原来是冷灰 `#eceef1`）。夜间模式那条没动 ——
  深底上压一层暖白会发糊。
- **鼠标停在「播放数据 + #话题」那一行现在也会高亮**了。它叠在卡片顶部、本身不是简介正文，
  以前停上去没反应；现在和「点整卡展开」保持一致，光标也变成手型。

## 变更 · 「播放页优化」的说明文案

感叹号提示换成「**播放页焕新视觉效果，带来更沉浸播放体验**」。

原来那句是功能清单（「标题与 UP 主信息移到播放器下方，右栏去掉分类条」）——
属于实现细节，不是打开面板时想知道的东西。

## 变更 · 首屏加载速度（播放页三处）

- **弹幕发送控件提前约 2.5 秒出现。** 窗口态 B 站在播放器下面挂一条 56px 的发送栏，
  我们把它整条隐藏、把本体搬进控制栏中间，但搬运原来固定等 3 秒。发送栏在**播放器自己的
  应用**里，根本不在左栏那棵树上，那个 3 秒对它不成立。现在只等播放器挂上（实测约 1 秒）
  就搬。**净效果：弹幕开关 / 输入框 / 发送键从「消失三秒」变成「一秒内就位」。**
- **顶栏骨架栏补两块灰占位**（搜索框 + 右侧那排图标）。首屏那 1~2 秒里真实顶栏还没长出来，
  原来只有一条白底 + logo，看着像「顶栏没加载」；现在是「logo + 灰占位」，一眼能看出在加载。
  只画灰块、不放任何可点的假控件（假界面点上去没反应，比空着更糟）。
- **首屏轮询提前收工。** 原来雷打不动跑满 6 秒（60 轮），每轮都要读一批元素尺寸、全是强制排版，
  而这 6 秒正是 B 站自己渲染的窗口。现在「观察器都绑上 + 卡片位置量出来」就收工（实测约 1.2 秒），
  之后的变化交给观察器，B 站 3.2 秒那次整栏重渲染照样能接住。

## 修复 · UP 主信息卡片「悬浮」/「往上窜」

这是这版花时间最多的一个问题，现象有两个方向：一次是停在视口中间、被涌上来的评论区埋掉；
一次是反过来「往上窜」、压到播放器和标题上。

- **悬浮的根因**：卡片钉不钉由一个 CSS 变量决定，而那个变量**不会自愈**。滚动时负责重算的
  函数根本不跑（B 站只在钉住位置变化时才写左栏的行内 top，观察器不响），所以一张悬浮卡
  会一直挂到下一次布局变化为止。实测把那个变量人为设成 `700px` 后滚动 6 个位置，
  偏差从 1276px 一路涨到 2676px。
- **往上窜的根因**：卡片和左栏的 sticky 包含块不同。评论加载完、左栏高度追上外层容器的那
  一帧，左栏会停止吸顶、跟着页面滚，卡片必须**同时**放开 —— 但这个「放开」原本排在
  `requestAnimationFrame` 里，比实际布局晚一帧。

  实测（1440×620 视口 / 快速下滑）：

  | 滚动位置 | 卡片顶边 − 标题底边 | 左栏余量 | 钉住值 |
  | --- | --- | --- | --- |
  | 1400 | 8px | 2974 | 276px |
  | **1750** | **1410px** ❌ | **0** | 276px（过期） |
  | 2100 | 8px | 0 | 已清空 |

  那一帧卡片钉在 276px、标题已经滚到 −1134px —— 就是看到的「窜」。

- **修法**：①「该不该钉」改成在尺寸观察器回调里**同步**判，观察器回调跑在「布局之后、
  绘制之前」，同一帧就能画对；②钉住位置改成**直接量标题**（`标题底边 + 8px`），
  不再用公式推 —— 两者数学上等价，但实测那一支能自动纠正「公式和 B 站实际写的值对不上」
  的情况。**仍然没有任何滚动回调**，滚动过程中一个字节都不写。

- **验证**：加载完成后连续采样 6 秒（40 次），「卡片顶边 − 标题底边」恒为 8px；快速下滑
  15 次采样，除被修掉的那一帧外全部为 8px。

## 修复 · 左栏评论上方那条「花生AI」站外推广横幅

- 位置：简介卡下面、评论区上面，102px 高的一条 —— 左边「花生AI也能做同款 / 输入文案一键成片，
  人人都能做视频」，右边一张封面图，整块是一个指向站外的链接。
- 它和已有的活动横幅占同一个位置、同一个高度，只是类名不同，所以原来那条屏蔽规则没命中。
  现在一并算进去，**顺便把它自带的那 24px 上下外边距也清零** —— 否则横幅藏了、外边距还在，
  左栏会留一条 48px 的空白。
- 只藏这一条、不藏整个资源容器：那个容器里还可能装稿件自带的资源（素材 / 下载），
  那是真内容，得留着。
- 实测（1440×900）：横幅 1050×102 消失，容器高度 102 → 0，评论区从「横幅下沿」上移到
  简介卡下沿，中间没有多出来的空白。

## 修复 · 播放页稳定性

- **观察器不再被反复拆建。** 以前首屏那 2 秒里，两套观察器会被拆了重建二十来遍，
  每次重建都会立刻回放一次初始回调（又跑一遍布局计算）。现在宿主没换过就只把后到的容器
  补绑到现有观察器上。
- **标题还没排版时不再写位置**。标题高度为 0 时量出来的是「标题顶边」，卡片会直接压在标题上
  —— 这是「刚打开网页控件挤在一起」的成因之一。
- **简介卡的「没有简介」判定**改成只认 B 站自己写的行内 `display:none`。原来按文本内容判空，
  数据还没到的那几百毫秒里它也是空的，会先画一个 `~` 占位再撤掉，首屏能看见闪一下。
- **拖动窗口时的重排节流到一帧一次**：原来一秒几十次，每次都强制排版。

## 更新方法

1. 下载 `bili-elite-1.1.5.zip`
2. **覆盖解压**到你现在放扩展的那个目录（路径不要变，浏览器记的就是这个路径）
3. 打开 `edge://extensions`（Chrome 是 `chrome://extensions`），找到「奶睿pro」，点「重新加载」
4. 回到 B 站刷新页面。右下角齿轮 → 面板底部应显示 `开发版本 1.1.5 v008`

> 首次安装：解压到固定目录（别删，浏览器每次启动都从这里读）→ 打开扩展管理页 →
> 开启「开发人员模式」→ 把解压出来的文件夹拖进去。
