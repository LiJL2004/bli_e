# 奶睿pro v1.2.0 更新公告

> **一句话**：这版主打「更快、更稳」—— 首页 / 搜索页 / 播放页的白边对齐成同一条 10px；
> 掐掉 B 站的埋点、广告投放、播放器质量上报（首页少 67 个请求、播放页少 40 个）；
> 播放页首屏不再被「读写交错的强制排版」拖慢 350ms，**首帧前那 1.3 秒也不再是一片黑**；
> 顶栏导航改成新标签页打开；顺带修掉首页首屏「震一下」、夜间模式的白卡与扫光。

送审包：`bili-elite-1.2.0.zip`（235 KB / 16 个文件 / `manifest.json` 在 zip 根目录）。

---

## 界面 · 三页同一条白边（10px）

以前首页和搜索页的左右留白是 `clamp(32px, 2.4vw, 72px)` —— **窗口一宽它自己就变宽**，
1920 下是 46px、2560 下是 61px，和播放页那条 10px 永远对不齐；而播放页左右各 8~14px、
中间 12px，三个数还都不一样。

现在全站一个数：`--bili-edge: 10px`。

- 首页 / 搜索页：`main` 的左右 padding 直接取它（实测首页 40.87 → 10，首列 41 → 10、
  末列 1647 → 1678，两页都排成 4 列 × 402px、gap 20）；
- 播放页：左右 10、左栏与右栏之间 10、播放器顶部 10（半顶栏开不开都是 10）；
- 播放器顶到窗口最上面只留 10px，不再像 B 站那样先按一屏高封顶再倒推宽度。

## 性能 · 掐掉埋点与广告投放

新增一条跑在**页面世界**的 `guard.js`（`world: MAIN`，`document_start`）：
埋点、广告投放、播放器质量上报一律回一个「假成功」的响应，而不是让请求失败 ——
报错会让广告位停在 loading 留下骨架，「没有广告」才是 B 站天天在走的分支。

| | 改前 | 改后 |
| --- | --- | --- |
| 首页请求数 | 177 | **110** |
| 首页 `data.bilibili.com/log` | 29 | **0** |
| 首页 `cm.bilibili.com`（投放+计费） | 4 | **0** |
| 播放页请求数 | 204 | **164** |
| 播放页 `data.bilibili.com/log` | 59 | **0** |

## 性能 · 播放页首屏快 350ms

「播放页优化」里原来有个坑：**写完 `<html>` 上的 CSS 变量，紧接着读几何**。
自定义属性是继承的，写一个就等于整棵树样式失效，下一次读会强制同步重算 ——
实测 3293 个元素 **10.5ms / 次**，而老的布局函数一轮里读写交错四次。

现在所有布局函数都是「先把要用的全读完 → 再统一写」，两次 `syncUpPin` 合并成一次，
只有 `--left-top` 真的变了才重读一次。

| | 优化开 | 优化关 |
| --- | --- | --- |
| LCP | 1420 / 1612ms | 1088 / 1228ms |
| 最长任务 | 380 / 454ms | 332 / 345ms |

改完播放页长任务从 4 个 / 最长 380~454ms 降到 **2 个 / 最长 224ms / 合计 447ms**。

## 播放页 · 首帧前不再是一片黑

B 站自己已经不做 poster 了（`.bpx-player-video-poster` 是个空元素、0×0），所以播放页从
「页面画出来」到「视频出画」之间，播放器区域一直是**纯黑**。这一段有多长？同机冷启动实测：

| | 直播页 | 视频页 |
| --- | --- | --- |
| 第一块内容（FCP） | 456ms | 924 ~ 1112ms |
| 最大一块内容（LCP） | 468ms（满屏背景图） | 1331 ~ 1600ms（视频首帧） |
| 首帧出画 | 2.7s | 1.33 ~ 1.66s |

也就是说「直播页看起来比视频页快」并不是视频页更重（它请求更少、字节更少、首帧还快一倍），
而是**直播页 0.45s 就有一张满屏背景图**，视频页在那 1.3 秒里什么都没有。

现在用封面顶上：封面地址来自首屏就带着的稿件信息（不用额外接口），取
`@672w_378h_1c.webp`（20.6KB），用伪元素铺在播放器上，**首帧一到立刻摘掉**，
另加 8 秒兜底与出错摘除 —— 万一视频加载失败，不会让封面一直盖着播放器。

- LCP **1596ms → 1192ms**（封面成了最大的一块绘制）；
- 黑屏 **1.46 ~ 1.59s → 0.66 ~ 1.0s**；
- 首帧本身没有被拖慢（三次 A/B 的差值是 −232 / +100 / +131ms，落在噪声里）。

顺带：**鼠标在卡片上停住时，会顺手把这张封面也预取下来**（`as=image`，浏览器最低优先级，
最多 8 张）。从首页 / 动态页点进播放页时，封面直接命中缓存，黑屏那段还能再早 200~300ms。

## 顶栏 · 导航在新标签页打开

顶栏的**首页 / 动态 / 消息 / 收藏 / 历史 / logo / 头像**，点下去都在右侧开新标签页，
当前页（正在播的视频、翻到一半的信息流）不会再被顶掉。搜索框仍然是当前页搜索。

## 性能 · 首页大 banner 的 28 张图层图不再下载

首页 header 那层动画 banner 是 28 张 7.3KB 的小图拼的（`/bfs/vc/*`），由 B 站的 Vue 应用
用 `img.src = …` 建出来 —— 属性赋值能拦。现在「首页优化」开着时这 28 个请求直接不发，
首页请求数 **140 → 110**，省约 200KB。

> 代价：banner 只剩静态底图，动画层不挂载（实测无碎图、无空洞）。关掉「首页优化」会
> **自动刷新一次**把动画层找回来。

## 优化 · 首页首屏不再「震」一下

以前首页刚打开 / 刷新时，整个屏幕会重排一次。量出来是两件事：

1. **滚动条晚到**：第一帧只有顶栏（文档高 753 < 视口），没有滚动条；信息流一渲染出来就溢出
   → 滚动条出现 → `clientWidth` 1584 → 1567，居中 / 贴右的东西全部横移 8.5px。
   现在滚动条常驻，宽度从头到尾都是 1567。
2. **楼层卡摘得太晚**：番剧 / 直播这类「楼层卡」先以骨架身份排进栅格、画出来，等数据到了
   才被摘掉 → 整行卡片左滑一格、下面所有行整体上移一行高（layout-shift **0.126**）。
   现在它们一插进来就是隐藏的，栅格第一次布局就没有它，后面再没有任何摘除动作。

改完最大 layout-shift **0.126 → 0.064**（剩下那点是 B 站自己换节点，被下面的淡入盖住）。

## 优化 · 卡片加载有了过渡

骨架换成真卡的那一帧，真卡现在会**淡入 + 上浮 8px**（220ms，`cubic-bezier(.22,.61,.36,1)`）——
这条曲线前段跑得快，所以从透明度 0 开始也不会被看成「空了一帧」；标准曲线前段太慢，
二十张卡同时淡入会整屏灰一下，那才真像闪。

## 修复 · 夜间模式：白卡、白边、扫光

- **加载中有一格是白卡**：夜间那条覆盖规则的选择器和白天不是同一条 —— 白天是
  「格子里装着骨架就算」，夜间只认「格子本身就是视频卡 / 楼层卡」，被包一层的特殊卡就漏了。
  现在两边逐字对齐。
- **白边**：B 站给楼层卡写死了 `border: 1px solid #e3e5e7`（不是变量，夜间不会跟着变深），
  白天看不见、夜里是一圈白。占位卡统一刷透明。
- **扫光**：B 站给每个骨架块挂了一层扫光叠层（`::after` + `1.2s` 无限循环），
  白天是「浅灰扫浅灰」看不出来，**夜里取的是 #232527 → #17181A**，一条黑带横着扫过灰块。
  现在整层摘掉，骨架就是一块静止的有光泽的灰。

## 修复 · 关掉「首页优化」后首页无限刷新

页面刚打开时配置里全是默认值，「首页优化」先按 `true` 挂了类；几十毫秒后存储里的真实值
`false` 回来，被误判成「用户刚把它关掉」→ 刷新 → 死循环。

现在这类「副作用型的开关响应」（重载 / 弹窗 / 发请求）只认**用户亲手点的那一下**，
存储快照和跨标签页同步一律不触发。

## 修复 · 全屏动画的按键监听抛错

页面（和别的扩展）会 `dispatchEvent(new Event('keydown'))`，那种事件上没有 `key` 属性，
`e.key.toLowerCase()` 直接抛错；它挂在 document 的**捕获**阶段，一抛错就中断同一事件
后面所有监听。现在先判类型再转小写。

## 升级注意

- **装完请到 `chrome://extensions` 点一次「重新加载」**，然后刷新已打开的 B 站页面。
- 这版新增了一个 `guard.js`（`world: MAIN` 的独立内容脚本），**manifest 变了**，
  不重新加载的话埋点 / 广告拦截不会生效。
- 「首页优化」开着时 banner 是静态底图（省 28 个请求）；想要动画层就在设置里关掉它，
  关掉会**自动刷新一次**。
- 播放页白边从 `8~14px` 统一成 10px，看起来会比之前略宽一点点 —— 这是三页对齐的代价。
- 播放页刚打开时会先看到**封面**、再切到视频画面 —— 这是有意为之（B 站自己不做 poster），
  不是加载出错；视频加载失败时封面会在 8 秒内自动撤掉。
