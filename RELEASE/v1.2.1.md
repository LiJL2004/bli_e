# 奶睿pro v1.2.1 更新公告

> **一句话**：这版全是「看着就差一格」的小毛病 —— 顶栏终于和三种页面的内容对齐到同一条竖线
> （动态页随后也并进来）、搜索页右侧那两根并排的滚动条去掉内侧那根、非半顶栏时播放器不再和
> 顶栏之间留一条白缝、大窗口下多余的「展开更多」不再出现、数字藏品头像的 UP 主卡片不再胖一圈；
> 导航语义也顺了一次：logo / 「首页」在本页打开，**搜索改成新标签页**。

送审包：`bili-elite-1.2.1.zip`（239 KB / 16 个文件 / `manifest.json` 在 zip 根目录）。

---

## 界面 · 顶栏和内容终于在同一条竖线上

以前顶栏的左右内边距写死 24px（照 B 站原生顶栏量的），而三种页面的内容区留白早在 1.2.0
就统一成了 `--bili-edge`（10px）—— 同一条竖线上，顶栏和内容各走各的，logo 比第一列卡片多缩进
14px，右侧「历史」又比卡片右边缘往里收一截。

现在首页 / 搜索页 / 播放页的顶栏直接取 `var(--bili-edge, 10px)`；动态页（t.bilibili.com）
按用户要求也并进来 —— 它的内容本身是居中三栏、没有「一条边」可对，但顶栏是全局导航，
跟视频页取同一个数更一致。消息 / 空间这些内容边距本来就不是 10 的页面，仍是 24px。

实测（1600×900）：顶栏 `padding: 10px/10px`、logo 左 10、右侧图标区右 1573 = `clientWidth − 10`，
和信息流栅格的左右边缘逐像素对齐。半顶栏有自己的一套内边距（左 16 / 右 12，贴着视频右边缘），
不受这条影响。

页面判定用的是 `location` 挂一个 root 类，**不是** CSS 的 `:has(main.bili-feed4-layout)` ——
后者要等信息流节点出现才匹配，那一下顶栏会从 24 横跳到 10，比一直不对齐还难看。

## 修复 · 搜索页右侧的两根滚动条

搜索结果页右侧并排两根竖向滚动条，外侧那根是页面的、内侧那根细的，两根各自都能拖，
内侧那条还把内容挤窄了 17px。

根因是 1.2.0 为首页首帧防横移加的「滚动条常驻」挂在了全站类上，而 B 站搜索页的 `body`
自己就是滚动容器 —— 于是 `html` 和 `body` 各出一条。

现在「滚动条常驻」单独拆成一个只在首页挂的类：搜索页 `html` 的 `overflow-y` 从 `scroll`
变回 `visible`，滚动条只剩 `body` 那一条（落在视口最右边）；首页那条照旧常驻。

## 修复 · 非半顶栏时播放器和顶栏之间的白缝

关掉「播放页半顶栏」后，播放器上边缘和顶栏下沿之间空着一条 10px 白条，像顶栏没贴住画面。

那 10px 本来是给半顶栏模式留的呼吸（半顶栏时左栏上移 64px，窗口边缘需要一点白）；
非半顶栏时顶栏还实打实占着上方那 64px，再留 10px 就成了一条缝。现在这个值跟着半顶栏状态走：

| | 半顶栏 | 非半顶栏 |
| --- | --- | --- |
| 播放器顶部留白 | 10px | 0px |
| `#mirror-vdcon` 的 padding | `10px 10px 0px` | `0px 10px` |
| 播放器上边缘 | 10 | **64**（= 顶栏下沿） |

左栏「钉住」的上限跟着用同一个数，滚一下不会再凭空多出 10px。

## 修改 · logo 和「首页」在本页打开

以前点顶栏左上角的 logo 或「首页」，右边会多开一个首页标签，原来那个还在播的标签页留在那儿。
现在这两个入口是本页导航：不是首页就跳首页，本来就在首页就刷新一次；
按住 Ctrl / Cmd / Shift / Alt 时**不拦**，交给浏览器 —— 那是你明确要新开标签。

顶栏其余导航（动态 / 消息 / 收藏 / 历史 / 头像 / 投稿）仍是新标签页，不打断当前页。

## 调整 · 顶栏搜索改成新标签页打开

在顶栏搜索框里搜完，搜索结果**在新标签页打开**，原来那页留着 —— 搜索页不是「当前这页的
下一页」，你搜完还要回到刚才那篇稿子 / 那个列表接着看。

回车提交、点联想词、点热搜、点搜索历史，四条路都走同一处逻辑。实测：首页搜「卡提希娅」
→ 标签数 1 → 2，新标签是 `search.bilibili.com/all?keyword=…`，原标签仍是首页。

## 修复 · 大窗口下简介的「展开更多」是多余的

大屏上简介正文只有两三行，收起态就已经把全文露出来了，左下角却还挂着「展开更多」；
点它（变成「收起」）卡片反而矮一截 —— 看着像「点开却收起了一些」。小窗口下一切正常。

根因是 B 站只在简介数据到的那一下判一次要不要折叠，折叠高度写死成行内 px；之后窗口变宽，
正文从 4 行缩到 2 行，那个 px 还是旧的。

现在判定权收回来（**不动 B 站的折叠机制**）：装得下就把行内高度放开、藏掉按钮，
装不下什么都不做、仍是 B 站那套。实测 2200×1000 造一段 214 字单段简介 → 卡片 136px、
正文 3 行全部可见、按钮不显示；缩到 1200 后自动恢复折叠。宽屏 / 网页全屏整块交回 B 站。

## 修复 · 数字藏品头像的 UP 主卡片胖一圈

用了「数字藏品头像」的 UP 主，播放页 UP 主控件上下的空隙明显比普通 UP 主大一圈，
卡片整体高 32px、把简介卡一起推下去。

B 站给这类头像的容器撑到了 **80×80**，可头像本身只画 54（放大 1.13 倍后居中），
右下角再挂一枚「数字藏品」角标 —— **画 54 占 80**，多出来的 26px 全是死空间。

现在按普通头像的原样钉回 48：容器、链接、头像三层一起，位移归零。那枚小角标留着
（它跟着头像缩到 13px，是 B 站全站通用的数字藏品标记）。实测同一批稿件，数字藏品头像
和普通头像的 UP 卡片高度、顶边位置、头像尺寸全部逐像素一致。

## 升级注意

- **装完请到 `chrome://extensions` 点一次「重新加载」**，然后刷新已打开的 B 站页面。
- 这版 `manifest.json` 只有版本号变化（`guard.js` 在 1.2.0 就有了），但内容脚本必须重新加载才生效。
- 首页 / 搜索页 / 播放页 / 动态页的顶栏会比之前**往左挪 14px**（24 → 10），
  这是和内容对齐的代价；其它页面（消息 / 空间 …）不变。
- **顶栏搜索现在是新标签页**；如果你习惯本页搜索，暂时没有开关，这是按需求统一成
  「除了 logo / 首页，其它导航都在新标签页」的结果。
- 数字藏品头像的 UP 主卡片会**比之前矮 32px**，头像也略小一圈 —— 这是回归正常尺寸，不是丢图。
