## 修复 · UP 主卡片「悬浮 / 往上窜」——让它老实待在左栏里

**现象**：播放页下滑时 UP 主信息控件不跟手。两个方向都出现过：一次是停在视口中间、
被涌上来的评论区埋掉；一次是反过来「往上窜」、压到播放器和标题上。

**根因**：卡片的 DOM 在右栏，靠 `position: sticky` + 一个 `top` 常量画到左栏第 3 行。
它的 sticky 包含块是 `#mirror-vdcon`（`max(左栏, 右栏)`），而左栏**自己也是 sticky**、
包含块也是 `#mirror-vdcon`。两者要永远对齐，前提是「位移量相等」：

    左栏位移空间 = mirror 高 − 左栏高        （`leftRoom`）
    卡片位移空间 = mirror 高 − up-y − 卡片高   （几乎总是很大）

只要 `leftRoom > 0`，两者都会位移到 `pinned`，卡片停在 `pinned + up-y` —— **恒等对齐**，
和 `pinned` 是正是负毫无关系。`leftRoom = 0` 时左栏被夹死跟着滚、卡片照样能钉，
这才是唯一会分家的情形。

**v006 走过一段弯路**：以为「`pinned < 0`（左栏比视口高、钉住后顶部出屏）说明钉着没意义」，
就一刀切不钉。结果左栏照钉不误、卡片改跟右栏滚，两者当场分家 ——
实测左栏钉在 `-223` 不动、卡片继续往上跑，相对偏移从 `1106` 一路掉到 `753`，
就是用户报的「往上窜」。**已回滚**，判据里留了注释说明为什么不能这么判。

**v007 的两道闸**（互补，任一命中就不钉）：
1. `leftRoom < 1` —— 预测：高度差一变就生效，管住「左栏根本钉不住」；
2. `left.getBoundingClientRect().top < pinned - 1` —— 实测兜底：左栏本该钉在 `pinned`，
   实际却渲染得更靠上，说明它已经在跟页面滚了，这时卡片再钉就是浮在半空。
   这条直接看「左栏到底钉住了没有」，比高度差更本质。
- 顺带把 `leftRoom` 的兜底从 `Infinity` 改成 `0`：`#mirror-vdcon` 被 Vue 换掉的那一帧
  以前等于「左栏随便钉」，恰恰是 `--up-top` 最容易算错的时候。

**验证**（真实 Chrome，2545 宽）：模拟两种状态各滚一遍，采样「卡片相对左栏的偏移」——
`room = 3000` 和 `room = 0` 两种情况下偏移都恒等于 `up-y`（1106），全程零漂移。

## 新增 · 右侧推荐视频封面大小

- 「界面优化 → 播放页优化」那张卡里多了一条滑块（`railCardConfig.ts`），
  **默认 320px = 现在的大小**，一个像素都不差。范围 220~400，步长 10。
- 实现是给 CSS 里原有的 `clamp(190px, 58%, 320px)` **整体乘一个倍率**
  （`--bili-vb-cover-scale`，默认 1），而不是直接写死 px：那三个数分别负责
  「窄窗口别太小 / 跟着右栏宽度走 / 宽窗口封顶」，只改上限的话窄窗口下拖滑块毫无反应
  （真正生效的是中间那个 58%）。乘倍率是唯一既保住三段响应式、又能整体缩放的写法。
- 卡片高度不用管 —— `.pic-box` 上有 `aspect-ratio: 141 / 80`，宽度变了高度自己跟。
  实测 620 右栏下：倍率 1 → 316×179、1.25 → 395×224、0.7 → 221×125。
- 上限收到 400（试过 420）：1440 那种窄右栏下文字那侧只剩 124px，标题会被挤成一列单字。
- **只在播放页优化打开时生效**：CSS 整段挂在 `html.bili-elite-video-beta` 上，

## 变更 · 多人合作投稿（创作团队）的 UP 主那一行

多人稿件（联合投稿）的 UP 面板是**另一套结构**，和单 UP 完全不是一棵树：

```
.members-info-container        padding-top: 18
  .membersinfo-normal
    .header                    「创作团队 5人」通栏灰条，44 高，右侧一颗折叠箭头
    .container                 行内 max-height: 102px + overflow: hidden（折叠态）
      .membersinfo-upcard-wrap × N     头像 40 + 名字 + 角色标签
```

- **「创作团队 N 人」那条横幅整条去掉。** 它占掉 44px，头像要等到标题下面 52px 才出现
  （单 UP 是 8px），整块信息区看着就散了；而且它自己是通栏灰底，比头像那一行重得多，
  把「UP 主控件」这个视觉单元切成了两段。
- 同时把上方两截内边距（container 的 18 + 12）一起清零 —— **头像顶边因此直接落在卡片顶边**，
  「头像 ↔ 标题 = 8、卡片 ↔ 简介 = 10」和单 UP 逐像素一致。
- **点赞 / 投币 / 收藏 / 分享那一排回到「和多个 UP 主同一行」。** 单 UP 时操作栏靠
  `align-self: center` 落在 48px 头像的中线上；多人卡片第一行是 40px 头像、下面还压着名字
  和角色标签，整卡 84 高 —— 再居中就掉到「名字」那一行去了。改成按顶边排
  （`align-self: start` + `margin-top: 10px` = 8 + 20 − 18），实测头像中线与操作栏中线
  都是 621，严丝合缝。
- **折叠能力没有丢。** `max-height` / `overflow` 一起放开（行内值是 B 站写的，只能
  `!important` 压）：折叠本来是靠横幅右边那颗箭头展开的，横幅一藏就没有展开入口，
  成员超过一行会被裁掉。放开后由 flex 自然折行，行距交给 `row-gap: 12px`；
  每张成员卡自带的 `padding-bottom: 20` 一并收掉（单行时它就是卡片底部一截凭空的空白）。
  实测把卡片压到 320px 宽：5 人折成两行、容器高 180、`overflow: visible` 没裁掉任何一张。
- 判据是 `.up-panel-container` 里有没有 `.members-info-container`（`syncUpKind()`），
  结果翻译成 `<html>` 上的 `bili-elite-vb-multi` 类 —— 换稿件时面板会被 Vue 整块换掉，
  所以这个检测跟着观察器反复跑（`lastMulti` 缓存一下，避免每轮 toggle 触发样式重算）。
- 沉浸式（宽屏 / 网页全屏 / 全屏）**一条都不生效**：那三种模式信息区整套交回 B 站，
  横幅照常显示、卡片留在右栏原位。

## 变更 · 「N 人正在看」挪到播放数据那一行

- 位置：播放数据那一行（`15万 · 76 · 2026-10-23 20:57:39 · #话题…`）的**最右端**，
  12px 灰色，和播放数据同一条基线。窗口窄、话题标签折行时，它跟着**第一行**靠右。
- 数据还是 B 站自己那一个节点（`.bpx-player-video-info-online`）—— **只读文本、写 CSS 变量**，
  一个节点都不往播放数据里插。那块是 Vue 高频重渲染的区域（见 §7 的注释），
  插节点会让它的「按索引 patch」错位。
- 用 `.video-info-meta::after` + `margin-left: auto` 贴右：meta 本来就是 flex 行，
  `::after` 是它的第二个 flex item，`.video-info-detail-list` 自动让出这块宽度
  （标签因此早一点点折行，可以接受）。没拿到人数时 `content` 兜底 `none`，
  伪元素根本不生成，一个像素都不占。
- `align-self: flex-start` 是必须的：meta 是 `align-items: center`，不加的话单行时
  这行字比播放数据低 3px（实测）。
- 数字由 B 站自己轮询刷新，`display: none` 不影响更新（实测隐藏期间 8 → 7 照样在变），
  所以观察器盯文本变化就够；发送栏被搬 / 控制栏重建时节点会换新，两处入口都会重绑观察器。
- 只在**窗口态**生效。宽屏 / 网页全屏 / 全屏整块交回 B 站原版 —— 和播放数据那一行的
  其他改造（§7）同一个前提。

## 变更 · 首屏加载速度（播放页三处）

- **弹幕发送控件提前约 2.5s 出现**。窗口态 B 站在播放器下面挂一条 56px 的发送栏，beta 把
  发送栏容器整条 `display:none`、把本体搬进控制栏中间 —— 但搬运原来固定等 3s
  （`MOVE_DELAY`，照「B 站 3.2s 整栏重渲染」定的）。发送栏在**播放器自己的 Vue 应用**里
  （`.bpx-player-*`），根本不在 `#mirror-vdcon` 这棵树上，左栏那轮重渲染冲不到它，
  那个 3s 对它不成立。现在只等「播放器挂上」（实测 ~1s）就搬，下限收到 700ms；
  发送栏本体晚到的那 100~300ms 由 120ms 一轮的重试兜住（`moveSendingBar` 现在返回
  `false` 表示「再试」）。**净效果：弹幕开关 / 输入框 / 发送键从「消失三秒」变成「一秒内就位」。**
- **顶栏骨架栏补两块灰占位**（搜索框 + 右侧那排图标）。首屏那 1~2s 里真实顶栏还没长出来，
  原来只有一条白底 + logo，看着像「顶栏没加载」；现在是「logo + 灰占位」，一眼能看出在加载。
  只画灰块、**不放任何可点的假控件**（假界面点上去没反应，比空着更糟）。
- **首屏轮询提前收工**。`pumpEarly` 原来雷打不动跑满 6s（60 轮），每轮 `layoutUp()` 要读
  6 个 `getBoundingClientRect` + 2 次 `getComputedStyle`，全是强制排版 —— 而这 6s 正是
  B 站自己水合的窗口。现在「观察器都绑上 + 卡片位置量出来」就收工（实测 ~1.2s），
  之后的变化交给 MutationObserver / ResizeObserver，B 站 3.2s 那次整栏重渲染照样能接住。

## 修复 · 稳定性（播放页）

- **观察器不再被反复拆建**。`bindObservers()` 以前无条件 `unbindObservers()` 再重建，
  而 `pumpEarly` 每 100ms 叫一次 —— 头 2s 等于把 MutationObserver 和 ResizeObserver
  拆了重建二十遍，每次重建都会立刻回放一次初始回调（又跑一遍 `layoutUp`）。
  现在宿主（mirror / 左栏 / 右栏）没换过就只把后到的容器（播放数据 / 标签行 / 简介）
  补绑到**现有**观察器上；观察器回调里也补了一次同样的补绑，节点被 Vue 换掉不会失联。
- **标题还没排版时不写 `--bili-vb-up-y`**。标题高度为 0 时量出来的是「标题顶边」，
  卡片会直接压在标题上 —— 这是「刚打开网页控件挤在一起」的成因之一。现在等下一轮再量。
- **兜底亮卡片的时机**（2s → 2.5s）先按当前布局再量一次，量得到就不强行加
  `up-ready`；不然卡片会带着默认的 `0px` 出现在错误的位置（看着像「悬浮窗」）。
- **简介卡的「没有简介」判定**改成只认 B 站自己写的行内 `display:none`。
  原来按 `textContent` 判空，数据还没到的那几百毫秒里它也是空的 —— 会先画一个 `~` 占位
  再撤掉，首屏能看见闪一下。
- **窗口 resize 节流到一帧一次**：拖窗口时 `resize` 一秒几十次，每次 `measure()` 都是强制排版。

## 修复 · UP 主卡片「悬浮」（压着评论区不走）

**现象**：播放页滚到评论区后，UP 主信息卡钉在半空、盖在评论上，怎么滚都不动。

**根因**：卡片的 `--bili-vb-up-top` 僵住了，而它**不会自愈**。
钉不钉由 `layoutUp()` 末尾的 `syncUpStickyTop()` 决定，可 `layoutUp()` 前面有两个早退
（标题 / 卡片高度为 0 —— Vue 换节点的那几帧必然命中）。只要早退正好撞上「左栏从钉得住
变成钉不住」的那一刻（评论加载完、左栏高度追上 `#mirror-vdcon`，`leftRoom` 归 0），
变量就停在上一次布局里：左栏早就跟着页面滚走了，卡片还钉在 `左栏钉住位置 + up-y`。
更糟的是滚动时 `layoutUp()` 根本不跑（B 站只在钉住位置变化时才写左栏行内 top，
观察器不响），所以这张悬浮卡会一直挂到下一次布局变化为止。
实测：把 `--up-top` 人为设成 `700px` 后滚动 6 个位置，偏差从 1276px 一路涨到 2676px，
`--up-top` 一个字节都没变 —— 和用户截图完全一致。

**修法**（三道，互相独立）：

1. **`syncUpPin()` 成为 `--bili-vb-up-top` 的唯一写入方，并排到 `layoutUp()` 所有早退之前。**
   判据只看左栏自己的状态（是不是真 `position:sticky`、包含块还有没有余量、`leftPinTop`），
   任何一条不满足就立刻清空变量（`top:auto` = 跟着左栏一起滚）。标题 / 卡片这一帧量不到
   也拦不住它。另外 `--up-y` 一次都没写出来时一律不钉 —— 不再钉在凭空的 top 上。
2. **纯 CSS 的最后一道闸**：`html:not(:has(.left-container.scroll-sticky)) .up-panel-container
   { top: auto !important }`。B 站把 `.scroll-sticky` 摘掉（左栏不再吸顶）的那一瞬间卡片
   立刻一起停钉，这条不经过 JS，观察器失联也拖不住它。
3. **`scrollend` / `visibilitychange` 兜底自愈**：一次滚动只触发一次，不进滚动路径、
   不影响跟手，但会把「观察器失联 / 变量僵死」压到最多一个滚动动作内自愈 ——
   顺便补绑 `#mirror-vdcon` 被整块换掉时静默失效的那套观察器。

**验证**（真实 Chrome，1440×900 视口）：制造 stale 状态后，旧逻辑滚动 6 次偏差持续增大；
新判据一次即清空（`--up-top` 移除、`up.top − title.bottom` 回到 8px）。
`scrollend` 在 Chrome 里按预期每完成一次滚动触发一次。

## 修复 · UP 主信息卡片「下滑时往上窜」

**现象**：播放页加载完、评论陆续到位之后快速向下滑，UP 主信息卡片会先往上「窜」一大截
再归位（上一版还出现过反过来的一路向上漂移）。

**根因**：卡片靠 `position: sticky` + `--bili-vb-up-top` 钉在标题下面 8px。左栏的 sticky
包含块是 `#mirror-vdcon`（高度 = max(左栏, 右栏)），评论加载完左栏追上 mirror，
`leftRoom` 归 0 —— 左栏从此不再吸顶、跟着页面滚，卡片必须**同时**放开。但这个「放开」
原本排在 `ResizeObserver` 回调的 `requestAnimationFrame` 里，比实际布局晚一帧：

实测（1440×620 视口 / 快速下滑 / BV1LkHA6oEkF）：

| scrollY | `up.top − title.bottom` | leftRoom | `--up-top` |

那一帧卡片钉在 276px、标题已经滚到 −1134px —— 就是用户看到的「窜」。

**修法**（两条）：

1. **「该不该钉」改到 `ResizeObserver` 回调里同步判。** 这一步只读 4 个尺寸、只写一个
   CSS 变量，不改动任何被观察元素的尺寸，不会触发 RO 循环；而 RO 回调跑在「布局之后、
   绘制之前」，所以同一帧就能画对，零延迟。真正贵的 `layoutUp()` 仍然甩 rAF。
2. **`syncUpPin()` 改成「以标题为锚」。** 左栏正吸住时直接量 `title.bottom + UP_GAP`，
   不再用 `leftPinTop() + up-y` 推。两者数学上等价（实测吸住期间 `title.bottom + 8`
   恒等于公式值 1065px，且**不随滚动变**，所以照样不需要滚动回调），但实测那一支能自动
   纠正「公式和 B 站实际写的 top 对不上」的情况 —— 也就是「跟踪标题的位置」本身。

**验证**：加载完成后连续采样 6s（40 次），`up.top − title.bottom` 恒为 8px；快速下滑
15 次采样，除被修掉的那一帧外全部为 8px。另外把 `--up-top` 人为设成过期值再滚 6 次，
旧逻辑偏差持续增大，新判据一次即清空。
