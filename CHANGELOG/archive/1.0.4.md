# 1.0.4

> 1.0.3 已送审。本版新增首页广告屏蔽、打磨了加载占位，顶栏渐变与夜间模式覆盖更完整；
> 动态页入口收纳移进实验室、默认关闭。设置面板滑块与开关的白色圆钮放大到 16px / 24px。

## 实验室 · 动态页入口收纳

- **动态页优化（默认关闭）**：把右侧「社区中心」横幅和顶部「发动态」编辑器
  收成左栏用户卡片底部的两个竖排按钮，把版面还给动态流。三栏布局、动态流列数、卡片
  外观都保持 B 站原样。
  1.0.4 从「界面优化」移进实验室并改为默认关闭 —— 它改的是整页版面，先观察一个版本；
  样式也改成按需注入，没开启时不会往动态页塞那份 CSS。
  两个原入口不搬 DOM，只是隐藏后由按钮代理点击 —— B 站改结构时最多是代理失效，
  不会把节点搬丢。原入口晚一步渲染也没关系，`.left / main / .right` 各挂了一个
  子节点观察器，卡片或横幅一到就补上。

## 变更 · 顶栏渐变

- **渐变回到老观感，但过渡拉长、走曲线**：上一版把遮罩整个去掉、只让白纱淡出，
  结果是顶栏下沿变成一条「糊着的带子」再接上清晰内容，边界还在。现在遮罩重新加回来
  —— 白纱和 `backdrop-filter` 一起淡，顶栏是真的「化」进页面里。
  区别在于节奏：老版本只遮最后 19px（70%→100%），24px 的模糊在三四十像素内直接归零，
  一眼看得出断口；新版从 44% 起步、走一条 S 形曲线（先缓、中间快、末尾再缓）铺满
  剩下 36px，模糊退到 0 的过程中没有突变点。
- **白纱不跟着遮罩同步掉**：过渡段里的字会半清晰地透出来（这是老版本就有的代价），
  所以 72% 处仍留 0.72 倍强度、86% 还有 0.40，等遮罩已经很淡了才一起收干净 ——
  透出来的是灰影而不是黑字，压在图标下方也不抢眼。底边那条 0.5px 发丝线跟着渐变
  一起消失（它本来就是渐变的一部分），不加投影。
- **夜间也能用上渐变**：夜间那条实色顶栏会把玻璃层整块盖住，等于开着渐变没反应。
  现在夜间换成同色系的深色渐变（`#1a1b1f` 0.98 → 0.96 → 0.86 → 0.62 → 0.26 → 0），
  段位与白天那条一一对应，遮罩两边共用，节奏一致。

## 变更 · 夜间模式

- **夜间模式同时打开 B 站原生夜间（各页面都能生效）**：B 站的主题有两套机制，
  按页面走 —— 首页 / 动态页认 `<html>` 上的 `bili_dark` 类；视频页、搜索页、历史记录、
  个人空间根本不看这个类，它们靠一张主题样式表：亮色时 `href` 是
  `bili-theme/light.css`（个人空间是 `laputa-css/light.css`），夜间就是把 `href`
  换成同目录的 `dark.css`。之前只加了类，所以在首页好好的，一换到视频页 / 搜索页
  就又是白的 —— 这就是「开了夜间模式，打开其他界面又没开」的原因。
  现在两种一起做：挂类 + 换主题表，六类页面（首页 / 视频 / 动态 / 搜索 / 空间 / 历史）
  实测全部变深。`light_u.css` 是基础色板不参与切换，`dark_u.css` 并不存在。
- **站内换页会补回来**：整页跳转时内容脚本重跑一遍；站内路由（首页点视频、顶栏切页）
  不重载文档，B 站会把主题表换掉或把类清掉 —— 现在挂了两个观察器盯着 head 里的
  `link` 和 `<html>` 的 class，被换回亮色就立刻补一次。白天（开关关着）直接返回，
  不产生任何查询。
- 关掉开关时只还原「我们改过的那几个」：用户自己开着的原生夜间不会被一起关掉。
- **动态页顶栏底下那条白边**：动态页的装饰底图是 `#app > .bg`（fixed、cover 的浅色
  pastel 图），B 站的深色没把它一起关掉。顶栏 64px、内容从 72px 开始，中间这 8px 的
  缝里就露出一条 rgb(130,144,144) 的横带，看着像顶栏底边长了一条白边。
  夜间把它换成页面底色（`var(--bg1)`），整页背板变平，缝和卡片区连成一片。
  这两个 div 只有动态页有，不用限定页面。
- **首页卡片在深色下重配色**（卡片边界 / 卡片确认）：描边从 `#d3d9df` 换成 16% 白
  （深底上约等于 #3a3d42，比卡片底亮一档）、悬停衬底从 `#e6e9ee` 换成 7% 白、
  蓝色描边提到 `#4aa8ff`（品牌蓝 `#00aeec` 压在 `#17181a` 上偏暗，2px 描边看不出是选中）。
  只换颜色，不动 outline 的宽度与 offset。

## 新增 · 首页广告屏蔽

- **推荐流里的广告卡直接摘掉**（界面优化，跟着「首页优化」开关走）：B 站把推广 item
  （`goto=ad`）渲染成一张普通视频卡，只在封面右下角多一个「广告」角标，混在推荐流里
  很难一眼认出。现在整格 `display:none`，栅格自动回填，不留空洞。
  判据用的是结构而不是文字：广告卡的角标是 `.bili-video-card__stats` 的**直接子元素**
  `.bili-video-card__stats--text`，而普通卡片的播放量 / 时长都多包了一层
  `.bili-video-card__stats--item`。所以「stats 的直接子元素是 text」只会命中广告卡 ——
  写成 `:has(.bili-video-card__stats--text)` 会把整页卡片全摘掉。

## 变更 · 首页加载占位

- **占位卡的观感回到 1.0.3**：灰块用 1.0.3 那版的斜向渐变 —— 底色 `#e9ecf0`，
  `linear-gradient(120deg, #e9ecf0, #eef1f5 46%, #e9ecf0)`，`background-size: 100% 100%`。
  一块静止的「有光泽的灰」，不做动画（呼吸和扫光两种都试过，用户觉得都不如这版）。
  背景必须写成 `background-image` + `background-size` 的组合，不能只写 `background`
  简写 —— B 站自己的 `background-color` 还在，简写会把它一起重置掉。
  顺带把骨架卡的底从 `#edf1f6` 调淡到 `#f7f9fc`：卡底太深会把灰块的渐变对比吃掉，
  一屏看下来像一片没有层次的浅灰。
- **哨兵那一格**：「首页预加载」把 `.load-more-anchor` 整块上移了（骗 B 站的加载判据），
  格子位置就空出来 —— 它的子节点有等量反向位移，但那是 B 站后插的，偶尔晚一两帧，
  那一帧里就是一个纯白洞。现在给哨兵自己补一块 `::before` 底色（同样反向位移回原位，
  `z-index:-1` 让真骨架盖在上面）。
- **空壳兜底**：栅格里偶尔有一个「有尺寸、但图片 / 骨架 / 文字全都没有」的格子
  （B 站把数据还没到的 item 先渲染成空盒子）。脚本给它打 `.bili-elite-cell-blank`
  铺一层和骨架一致的底，卡片流里不再冒出纯白洞。真卡片哪怕图没到也有标题文字，
  不会被误标。
- **骨架卡有自己的底了**：占位格的卡片壳有可能比骨架内容先出现，壳本身没有背景 ——
  那一两帧里整格是一块纯白，跟旁边已经填好内容的卡混排时看着像「挖空了一格」，
  也就是「加载动画没及时出来」。现在壳上铺一层比页面白深一档的浅灰（`#edf1f6`）
  + 12px 圆角：骨架还没画上去时它已经是灰格，灰块挂上后再叠一层更深的扫光块。
  **选择器写的是 `*:not(.load-more-anchor):has(...)`，不是 `.bili-video-card`** ——
  骨架格有时直接是栅格子项、有时被 `.feed-card` 包一层，写死类名会漏掉后一种，
  表现就是「样式明明在，骨架还是白卡、还是直角」。
- **尾部不再留一片白**：两个来源。
  ① 格数对不齐：B 站固定只插 15 个骨架格（按它自己的 5 列 × 3 行算），加上哨兵
  那一格常常除不尽列数，最后一行右边就空出几格；卡片调小、列数变多时更明显。
  ② 内容不够一屏：加载中的页面比视口短，滚到底时下面直接是空白。
  现在按实际列数把骨架格克隆到栅格尾部：先补满最后一行，内容还不到一屏时再补到
  视口底部（最多 8 行）；尾部一变回真卡就整块撤掉。克隆的是现成的骨架卡，灰块、
  呼吸、圆角都跟着走；外面包一层 `display: contents` 的壳，格子直接成为栅格子项，
  壳本身不占位、也不参与 B 站按 nth-of-type 写的行距。
  两个坑：栅格尾部经常是楼层卡（番剧 / 直播那类）的骨架，照它克隆会补出一排番剧卡，
  模板必须挑普通视频骨架卡；另外 `display:none` 的格子（被「首页优化」藏掉的轮播、
  楼层卡）在 children 里但不占栅格位置，算行尾对齐时必须按 `offsetHeight` 剔掉。
- **楼层骨架卡的白底**：B 站给番剧 / 直播这类特殊卡的骨架铺了纯白卡身
  （`.floor-card` 和 `.floor-card-inner` 都是 `#fff`）外加一圈叠层阴影，
  混在视频骨架里就是一格「只有边框、里面全白」的空洞。卡身、内层、叠层一起刷透明，
  只留上面那层统一底色。
- **骨架格不再描边**：「卡片边界」原本也给占位格描了一圈灰边，把那些白缝圈了出来；
  占位格里还没有可点的内容，描边一律摘掉。
- **夜间也跟着变深**：浅灰卡底铺在 `#0a0b0c` 上是一整块发光的白板，夜间换成
  6% 白的卡底 + 14% ↔ 22% 白的灰块，呼吸幅度与白天一致。
- **加载期间底部那条大灰条**：页面比视口短的时候，B 站那层白底内容容器只包住已有
  内容，下面直接露出 `body` 的 `#f1f2f3` —— 看起来就是「骨架没画完，底下压了一条
  灰带」。给内容容器补上 `min-height: 100vh`，加载过程中那条灰带不再出现。

## 优化 · 主线程占用

- **评论区图片背景的扫描**：PhotoSwipe 的 `.pswp` 是从 `document` 的 MutationObserver 里发现的，
  首页滚动时每批 DOM 变化（一批几十个新增节点）都要扫一遍。原来每个节点都用
  `querySelectorAll(".pswp")`，要解析选择器、遍历整棵子树；现在换成
  `getElementsByClassName("pswp")`，不解析选择器、没命中直接返回，也不做数组拷贝。
  行为完全一致（仍然是「先看自己、再看子树」）。
- **空壳格子的判据顺序**：`markBlankCells()` 每个 sync（200ms）都要过一遍栅格。原来先算
  `textContent.trim()`（要把整棵子树的文本节点串起来），再查选择器 —— 真卡片全在第一步
  白算。现在先查 `img / picture / 骨架`，命中就短路，`textContent` 只留给真正的空壳。
- **去掉重复常量**：图片开合的时长和缓动曲线原来在 `imageViewer` / `imageStyle` /
  `imageGlass` 里各写了一份，改成从 `imageViewer` 统一导出 —— 少三处会不同步的字面量。

## 变更

- **滑块与开关的白色圆钮一起放大**：滑块圆钮 14px → **16px**（轨道仍 18px）、
  开关圆钮 20px → **24px**（轨道仍 44×26），四周留边分别从 2px / 3px 收到 **1px** ——
  圆钮和蓝色边缘几乎相切，不再像「浮在槽里」。两个控件现在都是「轨道高 - 2px」的比例。
  滑块填充的右边界仍按「滑块中心 + 半个滑块 + 留边」算，拉到两端时蓝条正好比圆钮大一圈；
  开关的行程仍是 18px（44 - 24 - 1×2），拨到右边时右边同样只留 1px。
