# 1.0.1

> 1.0.0 已上架 Microsoft Edge 加载项商店，本版本在其基础上做性能与工程化改进。
> 约定：同一版本内的每次改动追加一条一句话概述；开发序号（设置面板里的 `vNNN`）
> 的递增本身不记入本文件。

## 性能

- **首页信息流扫描改为「按类名过滤 + 每秒最多一次」**：`PAGE_LEVEL_SELECTOR` 的注释
  写着「只扫几十~一两百个元素」，实际是 `body` 往下 6 层 ≈ 首页 9000+ 个节点，而
  `sync()` 在滚动时每 200ms 跑一次，每个节点都 `getComputedStyle()` 会强制样式重算 ——
  实测这一项把空闲主线程占用从 0.6% 拉到 24%。现在先用 `/bar|nav|header|breadcrumb|tab/i`
  过一遍 class 名（9000 → 一两百），整体再节流到每秒一次。
- **骨架扫光动画只留给尾部楼层骨架**：卡片里的 `.bili-video-card__skeleton--*` 在内容
  加载完后不会从 DOM 消失、只是塌成 0×0，却常驻 60 个 `background-position` 无限动画
  （首页 `document.getAnimations()` 实测 63 个）。`background-position` 是非合成属性、
  每帧重绘，实测空闲占用因此从 0.6% 涨到 35%。现在卡片骨架保留静态灰底 + 渐变，
  动画只挂在 `.floor-skeleton .skeleton-item`（3 个，正是「正在加载」的那几格）。
- **首页预加载的哨兵检查从常驻轮询改为 `IntersectionObserver`**：原来不管页面滚到哪都
  每 800ms 查一次 `.load-more-anchor` 的矩形（强制布局）；现在只有它进入「视口底部 +
  200px」（与 B 站判据同值）时才开那个补发 `scroll` 的定时器，离开即停，不在底部时开销为零。

## 界面

- 设置面板「界面优化」页最末一行新增**开发版本标记**（形如 `开发版本 1.0.1 v001`），
  用来判断用户装的是哪一次构建；样式为 11px 右对齐浅灰，可选中复制。

- **新增「奶睿设置键」**（界面优化，默认关闭）：开启后右下角悬浮球由 ⚙ 换成奶睿形象
  （`extension/assets/panel-mascot.png`，192×192 透明 PNG，原图白底用洪水填充抠掉、
  保留眼睛与牙齿内部的白），外圈白色描边 + 黄色光晕；图片已登记进 manifest 的
  `web_accessible_resources`。刻意没做呼吸动画 —— 常驻动画就是每帧重绘，和刚砍掉的骨架动画同类。

## 工程

- `package.json` 版本 1.0.0 → **1.0.1**（manifest 的 version 构建时读它）。
- 新增 `CHANGELOG/<商店版本>.md` 约定，并把「每次改动 vNNN +1、换版本号时重置为 v001」
  写进 `.opencode/skills/bili-elite/SKILL.md` 的「版本、发布与图标」一节。
- 同步修正 SKILL.md 里过时的图标说明（现在 `icons` 用 16/48/128 三档，
  `action.default_icon` 是 `{16,32,48}`，`icon-512.png` 已不被引用）。
- **移除 `simple-git-hooks` / `lint-staged`**（`postinstall` 与两段配置一起删）：仓库放在
  UNC 路径（`\\wsl.localhost\…`）上时 `pnpm lint-staged` 必然失败 —— `pnpm` 是 `.cmd`，
  `cmd.exe` 不支持 UNC，会退到 `C:/Windows` 报 `ERR_PNPM_NO_IMPORTER_MANIFEST_FOUND`，
  在 VSCode 里点提交就卡在「Preparing lint-staged…」。现在提交不再跑钩子，需要 lint 时
  在 WSL 里手动 `pnpm lint`。
- **README 精简为「功能总览 + 许可证」**：安装 / 构建、换图标、目录结构、已知限制这些开发侧内容
  移到本地 `DEVELOPMENT.md`（已加入 `.gitignore`，不上传）；README 里的「哔哩哔哩」也改成
  「B 站」，与商店描述口径一致。
