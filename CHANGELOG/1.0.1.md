# 1.0.1

> 1.0.0 已上架 Microsoft Edge 加载项商店，本版本在其基础上做性能与工程化改进。
> 约定：同一版本内的每次改动追加一条一句话概述；开发序号（设置面板里的 `vNNN`）
> 的递增本身不记入本文件。

## 性能

- **首页信息流扫描改为「按类名过滤 + 每秒最多一次」**：`PAGE_LEVEL_SELECTOR` 的注释
  写着「只扫几十~一两百个元素」，实际是 `body` 往下 6 层 ≈ 首页 9000+ 个节点，而
  `sync()` 在滚动时每 200ms 跑一次，每个节点都 `getComputedStyle()` 会强制样式重算 ——
  实测这一项把空闲主线程占用从 0.6% 拉到 24%。现在先用 `/bar|nav|header|breadcrumb|tab/i`
  过一遍 class 名（9000 → 一两百），整体再节流到每秒一次。
- **骨架扫光动画只留给尾部楼层骨架**：卡片里的 `.bili-video-card__skeleton--*` 在内容
  加载完后不会从 DOM 消失、只是塌成 0×0，却常驻 60 个 `background-position` 无限动画
  （首页 `document.getAnimations()` 实测 63 个）。`background-position` 是非合成属性、
  每帧重绘，实测空闲占用因此从 0.6% 涨到 35%。现在卡片骨架保留静态灰底 + 渐变，
  动画只挂在 `.floor-skeleton .skeleton-item`（3 个，正是「正在加载」的那几格）。
- **首页预加载的哨兵检查从常驻轮询改为 `IntersectionObserver`**：原来不管页面滚到哪都
  每 800ms 查一次 `.load-more-anchor` 的矩形（强制布局）；现在只有它进入「视口底部 +
  200px」（与 B 站判据同值）时才开那个补发 `scroll` 的定时器，离开即停，不在底部时开销为零。

- **骨架扫光动画最终整段去掉**（发版前复核）：上一版把 63 个动画砍到 9 个（只留尾部
  楼层骨架），但 9 个 `background-position` 动画仍然是每帧重绘 —— 首页实测空闲主线程
  **23.7%**，关掉后 **6.5%**（同一会话里连续取 6s 的 `TaskDuration`，同期 `ScriptDuration`
  只有 11ms，时间全花在绘制上）。也试过改成合成层的 `transform` 扫光
  （`::after` + `translate3d`），本机实测反而更高（29%），于是直接退回静态占位：
  一层 120° 的柔和渐变，主线程彻底安静。

  用来判断用户装的是哪一次构建；样式为 11px 右对齐浅灰，可选中复制。

- **新增「奶睿设置键」**（界面优化，默认关闭）：开启后右下角悬浮球由 ⚙ 换成奶睿形象
  （`extension/assets/panel-mascot.png`，192×192 透明 PNG，原图白底用洪水填充抠掉、

  `web_accessible_resources`。刻意没做呼吸动画 —— 常驻动画就是每帧重绘，和刚砍掉的骨架动画同类。

  现在底色是 `#FFD338` + 一层 `radial-gradient` 铺满整个圆盘，光晕从角色身后开始向圆外弥漫，
  圆内不再有空隙（`background-size` 86% 只留一点点呼吸空间）。
- **新增「奶睿顶栏图」**（界面优化，默认关闭）：把左上角自绘字标（76×34 的 B 站字标 mask）
  换成电视造型的奶睿插画（`extension/assets/logo-mascot.png`，128px 高，白底棋盘格用
  低饱和 + 高亮度判据洪水填充抠掉）。保持 34px 高、垂直居中、`left: 24px` 不变，
  宽度收到 42px，**不加光晕/阴影**，视觉上就是原来那个位置上的图标。

- **「奶睿设置键」对齐原版尺寸、去掉白描边**：52px → **44×44**（与原 ⚙ 完全一致），
  去掉 `0 0 0 2px` 的白色描边环，只留黄色光晕；顺带清掉了上一次改动残留的两条重复
  `:hover/:active` 规则（重复块会把新样式覆盖掉）。
- **「奶睿顶栏图」放大并右移**：42×34 → **48×38**，加 `margin-left: 8px`，
  视觉重心落在原字标的位置上，比原字标略大一点。

- **新增「个性设置」分类，与「界面优化」并列**：奶睿设置键 / 奶睿顶栏图从「界面优化」

  「按个人喜好改外观 / 整体重置」，和界面布局开关不是一类。开发版本标记跟着这一页走。
  分组名由 `features.ts` 的 `group` 决定，`settingsPanel.ts` 用 `PERSONAL_GROUP` 常量
  往这一页追加「设置管理」卡片。

- **隐藏动态页右侧的「回到旧版」按钮**：动态页（t.bilibili.com）侧栏里那枚 40×40 的
  旧版入口和「回到顶部」是同一个 `div.bili-dyn-sidebar__btn`，用
  `:not(:has(.back-top))` 只排掉旧版那枚，回到顶部保留（`topbar.css` §17.1）。

- **移除工具栏弹窗（popup）**：`action` 只留 `default_icon`，点工具栏图标走浏览器自己的
  扩展菜单（Edge 会列出「网站访问权限 / 管理扩展」等默认项），不再弹出一个和页面内
  ⚙ 面板重复的开关列表。`src/popup/`、`vite.config.mts` 的入口、`scripts/prepare.ts`
  的 views 一并删掉。

## 修复

- **点「刷新」之后首页预加载不生效**：预加载的保活定时器由 `IntersectionObserver` 把关，
  而哨兵被 §11 上抬了 150vh —— 用户停在信息流真实底部时，哨兵其实落在视口**上方**，
  `isIntersecting` 是 `false`，定时器被关掉；B 站自己的加载判据又只在 `scroll` 里跑，
  于是底部那批骨架永远等不到下一批内容。现在「哨兵在视口上方」（`boundingClientRect.bottom < 0`）
  也算在触发范围内。刷新后尤其明显：B 站重建信息流、页面跳回顶部，哨兵位置全变了。
- **设置面板 → 选项页的路径文案**：选项页写的还是「界面优化 → 设置管理」，
  改成「个性设置 → 设置管理」。

- **右下角新增「返回顶部 / 刷新」两枚浮动键**（`floatingButtons.ts`，挂在设置键 ⚙ 上方
  10px）：白底黑图标的 44×44 圆钮，图标是自绘 SVG（顶栏横线 + 向上箭头 / 顺时针圆弧）。
  按页面类型给键，**没有的键不渲染、剩下的自然下移补位** —— 首页两枚都有，动态页 /
  搜索页 / 视频页只有返回顶部；返回顶部滚过 200px 才出现（与 B 站原生同款行为）。
  「刷新」优先复用 B 站自己的「刷新内容」内层节点（`.flexible-roll-btn-inner`），
  只重取推荐流、不重载整页；找不到才退回 `location.reload()`。

- **原生浮动按钮收进设置**：新增「原生刷新按钮屏蔽」「原生返回顶部按钮屏蔽」两个开关
  （界面优化，默认开）—— 前者收掉首页的「刷新内容」和信息流里的「换一换」，后者收掉
  首页 / 搜索页 / 视频页的「顶部」与动态页的「回到顶部」（四家类名互不相同，一条一个
  选择器，见 `topbar.css` §17）。「…」三点菜单与「客服」没有开关、**始终隐藏**，
  客服外面那层 `div` 一起收掉（否则 flex 列里留个空档）。

  在 WSL 里手动 `pnpm lint`。

  移到本地 `DEVELOPMENT.md`（已加入 `.gitignore`，不上传）；README 里的「哔哩哔哩」也改成
  「B 站」，与商店描述口径一致。
- **收尾时合并重复的屏蔽规则**：动态页「回到旧版」原本单占 `topbar.css` §10.2，发版前并入
