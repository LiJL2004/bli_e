# 1.1.3

> 小版本：四处收尾 —— 视频进入**宽屏 / 网页全屏 / 全屏**时轮盘不再接管呼出键；
> 宽屏切换补上一段 FLIP 动画（「动效增强 → 宽屏模式动画」可单独关）；
> 设置面板的开关把「点下去鼓一下」的手感找回来了；
> 轮盘选中的页面默认改成**新标签页打开**（快捷功能里可改回当前标签页）。

## 修复 · 后退回来停在原地（同源跳转时失效）

- 记录里存的是**出发页**的地址，而跳去的目标页也会跑同一个内容脚本。原来在解析完记录后
  立刻 `removeItem`，于是「视频页 → 首页 / 番剧 / 历史」这类**同源**跳转，记录在目标页
  就被吃掉了，按后退回来已经什么都不剩 —— 只有跨域目标（动态 / 空间 / 消息 / 直播，
  `sessionStorage` 按 origin 隔离）才侥幸生效。这也是「有时灵有时不灵」的来源。
- 现在先校验地址与时效、确认是「回到出发页」的那一次加载，再删记录。对不上 / 已过期的
  那份不删，由十分钟的时效兜着，不会误伤别的页面。

## 修复 · 绑定按键后关面板，轮盘呼出键会失效

- 面板关掉时只清了轮盘那颗「呼出按键」的绑定态，漏了新加的「快速使用设置面板」那颗。
  `listeningPanelKey` 残留为真会让 `setWheelKeyCapturing()` 一直置位 —— 轮盘从此不接管
  呼出键；而且下一次任意按键（包括在评论区打字）都会被当成「正在绑定」吃掉，静默改写
  成新的面板呼出键。
- 关面板时两颗一起清；按键监听里再补一道兜底：面板没开着就说明绑定态是残留的，就地复位。

## 调整 · 两颗呼出键撞车时互换

- 轮盘的监听挂在 `window`、面板挂在 `document`，前者先拿到按键。两颗键设成同一个时，
  面板那颗会被轮盘整段吃掉，看上去就是「设了没反应」。现在绑定时撞上了就把旧键交给对方，
  两边都还能用。

## 调整 · 轮盘圆心按布局视口算

- `position: fixed; inset: 0` 的居中基准是**不含滚动条**的 `clientWidth`，原来用 `innerWidth`
  取中点，横向差一个滚动条宽度（约 7px），角度分界会整体偏一点。改读 `clientWidth` /
  `clientHeight`，不再有这处偏差。

## 性能 · 一处小改

- `playerMode` 盯 `body` 类名的那个观察器加了预判：既不在网页全屏、当前结论也不是网页
  全屏时直接跳过（`data-screen` 与原生全屏各有自己的触发源），省掉每次 body 改类名的一次
  全文档 `querySelector`。
- 其余待办（15 次 `storage.sync.get` 合并成一次、`body` 的三个观察器合一、设置面板 DOM
  懒建）改动面较大，留到下一个版本单独做，不和本次修复混在一起。

## 新增 · 宽屏模式动画

- 播放器右下角的「宽屏」不再瞬间撑开：进入 / 退出各一段 FLIP（进入 280ms、退出 240ms，
  与网页全屏同一套曲线），播放器从原尺寸长到铺满版面宽度、右栏跟着让位。
- 开关在设置面板 → **动效增强 → 宽屏模式动画**（`wideAnim`，默认开）。
  它和「网页全屏动画」是两条独立的路：宽屏只把播放器撑宽、不接管整屏，
  时间线也互不重叠（只在 `normal ↔ wide` 之间播，进出网页全屏 / 全屏各走各的）。
- 为什么只能靠 `data-screen` 触发：B 站切宽屏没有可以拦的事件，而且属性一改，
  容器尺寸在同一次布局里就已经是终态（实测 963×588 → 1218×728，MutationObserver
  回调里量到的就是终值）。所以「从哪儿开始」用的是**切换之前**快照下来的 rect
  （`pointerdown` / `scroll` / `resize` 各记一次），不是在回调里现量。
- 尊重系统「减少动态效果」：直接瞬切（`flipVideo` 里 `prefersReducedMotion()` 早退）。

## 变更 · 全屏 / 宽屏时轮盘不接管

- 视频进入**宽屏、网页全屏、全屏**之后，呼出键不再弹出轮盘，这次按键原样还给浏览器
  （全屏里的 Tab 本来就该是焦点导航）。退出之后下一次按键自动恢复 —— 判定是每次按键
  现算的，没有需要维护的状态机，也就没有「退出了但还记着全屏」的可能。
- 轮盘开着的时候进了这几种模式：直接收掉（挂在那儿的轮盘既点不到也选不了，
  指针一动还会选格）。
- 判定集中在新的 `playerMode.ts`：`data-screen`（`normal` / `wide` / `web` / `full` / `mini`）
  + body 类名兜底（直播站没有 `data-screen`，只有 `player-full-win`）+ `fullscreenElement`。
  轮盘与宽屏动画共用同一份判断，不会再出现「一个认得出全屏、另一个不认」的情况。

## 修复 · 开关切换时的放缩被悬停动画吃掉

- 现象：上一版给开关加了悬停动效（拇指放大 1.09 再收回）之后，**点开关时那一下「鼓起来」
  没了**，只剩拇指平移。
- 原因：两条动画写的都是 `animation` 简写，最终只可能有一条生效，而决定权在**特异性**上，
  不是先后顺序 —— 悬停那条是 (0,5,0)（`.item` + `:not(.is-disabled)` + `.switch` + `:hover`
  + `.thumb`），切换那条只有 (0,3,0)。点击时鼠标必然停在开关上，于是切换放缩每次都被整段吃掉。
- 现在三条动效各占一个属性，互不打断：
  - `translate` = 拇指位置（原来是 `transform: translateX(18px)`）
  - `scale` = 悬停时弹一下（不变）
  - `transform` = 按下挤压（`scaleX(1.32)`，1.0.2 的手感，没动）+ **切换时鼓一下**
- 切换放缩用类名 `.is-toggle` 触发（`settingsPanel.ts` 的 `popThumb`），不用 `input:checked`：
  `:checked` 只能覆盖「打开」那一次，关掉时规则被移除、等于没有动画。
  连点也能重播（先摘类 → 强制一次样式计算 → 再挂回去）。
- 选择器写成 `.item:not(.is-disabled) .switch.is-toggle .track .thumb`（(0,6,0)）：
  必须**严格高于**悬停那条，靠「后声明」是赢不了的。
- 类名的摘除交给 `pointerleave`，不用定时器：动画一播完就摘类，悬停动画会因为「重新命中」
  而从头再播一遍（鼠标还停在开关上），观感是连弹两下。等指针离开再摘，两条各播一次；
  连点同一颗开关仍然每下都重播（`popThumb` 每次都会先摘再挂）。
- 动画不写 0% 关键帧，起始值取当前值 —— 否则第一帧会把拇指从按下的挤压态（1.32）
  硬拽回 1，看着像掉了一帧。
- 「减少动态效果」下不播（覆盖规则也要写同样的选择器，否则 `animation: none` 会被压掉）。

## 新增 · 轮盘默认在新标签页打开

- 以前轮盘选中哪一格，就在**当前标签页**跳过去；现在默认开在**新标签页并自动切过去** ——
  视频看到一半用轮盘去「历史 / 动态」，不会再把当前这个视频顶掉。
- 想回到原来的行为：设置面板 → **快捷功能 → 更改默认值为当前标签页打开**（`wheelCurrentTab`，默认关）。
  轮盘关掉时这一行跟着变灰（`under: quickWheel`，与「顶栏渐变」同一套）。
- 轮盘中心会提前说明白：当前标签页模式写「松开前往」，新标签页模式写「在新标签页打开」——
  松手之后当前页纹丝不动，不说一句很容易被当成「没生效」。
- 已经在目标页上时仍然只是收起轮盘，不跳转（新标签页模式也不会开一个重复的页）。

实现上不能直接用 `window.open`：这条路大多从 `keyup`（松开呼出键）里走出来，而浏览器只认
`keydown` / `mousedown` 这类「激活触发事件」—— 按住超过 5 秒再松手就超出了 transient
activation 窗口，`window.open` 会被弹窗拦截器默默吃掉。内容脚本也拿不到 `chrome.tabs`
（不在内容脚本的 API 集合里），所以消息转给后台，由后台 `tabs.create({ active: true })`
建标签页。后台**必须**回一个 `sendResponse`：不回的话内容脚本收到的是「message port
closed」的 `lastError`，于是又走一遍兜底，同一个页面被打开两次。

## 变更 · 三处文字说明收进感叹号

- 「呼出功能轮盘」上方那行灰字（按住呼出键 → 移动鼠标 → 松开前往 / 只在这三类页面生效 /
  三种播放器模式不接管）、「卡片大小」与「预加载范围」滑块下面那两行灰字，统一收进
  **紧跟在汉字右边**的灰色感叹号：悬停弹出小面板，不再白占行高、也不用每次开面板都读一遍。
- 三处都用同一个 `hintDot()`（`settingsPanel.ts`），提示卡朝**下**弹、向**右**展开：
  这些行都在内容区里，往上弹会被 `.panel-body` 的滚动裁掉；感叹号紧跟在汉字后面，
  往左展开会压到左边的分类栏。
- 感叹号只做悬停提示：不设 `tabindex`、不绑点击、光标是 `help`；圆圈的悬停放大只作用于
  圆圈本身（提示卡是它的兄弟节点 —— 挂在同一个父级上会跟着 `transform` 一起放大）。
- 挂提示的卡片不能 `overflow: hidden`（会裁掉探出卡片边界的提示），改由渲染后统一打
  `.is-tip` 标记，首 / 末行补上圆角，等效于裁切。
- 文案标点统一：说明里不用句号，句中改分号，句末的直接去掉。

## 新增 · 设置面板呼出快捷键

- 快捷功能页多了一张卡：**快速使用设置面板**（`panelHotkey`，默认开）+ 一颗感叹号说明
  「使用快捷键打开或关闭设置面板」+ 一行「呼出按键」，默认键盘左上角那颗 `` ` ``（`Backquote`）。
  按一下开、再按一下关，不用每次都把鼠标挪到右下角点 ⚙。
- 存的是 `KeyboardEvent.code` 而不是 `key`：`` ` `` 和 `~` 是同一个键的两种状态，
  `code` 恒为 `Backquote`，中英文输入法、Shift 状态都不会让判定失效。
- 全站生效（不像轮盘只在那几类内容页）：` 键在 B 站页面里没有别的用途，抢它不破坏任何既有操作。
  输入框 / 文本域 / 可编辑区里不接管，评论区和搜索框照常能打这个字符。
- 按键存在自己的 `bili-elite-panel-hotkey`（`panelHotkeyConfig.ts`），与开关
  （`bili-elite-settings`）、轮盘（`bili-elite-wheel`）互不干扰；「恢复默认设置」会一起复位。
- 两颗「呼出按键」胶囊互斥：点其中一颗会先把另一颗的绑定态收掉；绑定时按 Esc 取消、
  只按修饰键不算数。轮盘开着时按面板键会先收轮盘再开面板，不会两层叠在一起。

## 调整 · 轮盘的新标签页插在当前标签页右边

- 以前 `tabs.create` 不传 `index`，新页被甩到标签栏最末尾 —— 跳一下得在几十个标签里找它。
  现在传 `sender.tab.index + 1`，插在当前页右边，和「点链接 / 从视频页跳走」时是同一个位置。
- 不传 `openerTabId`：它会把两页绑成「打开者 / 被打开者」，在标签分组里还可能被一起归组 ——
  轮盘只是跳转，不是从这一页派生出去的子页面。

## 变更 · 当前标签页打开后，后退回来停在原地

- 「更改默认值为当前标签页打开」开着时，从轮盘跳走再按后退，以前会回到一个**重新加载过、
  停在顶部**的页面。现在离开前记下滚动位置与文档总高度，回来后按回去。
- 说清楚做不到的那一半：**后退仍然是一次整页重新加载**。浏览器本来有 bfcache（后退直接复活
  内存里的旧页面），但 B 站自己把它关掉了 —— 首页注册了 `unload` 监听，另有一批
  `beforeunload` 与常驻心跳连接（实测 `navigation.type` 是 `back_forward`，但
  `pageshow.persisted` 恒为 `false`）。这一层是站点的，扩展改不了。
- 所以做的是「回来之后看到什么」：先设 `history.scrollRestoration = 'manual'` 关掉浏览器
  自己的滚动恢复（它会跟我们的推回打架），把 `<html>` 垫到离开时的总高度（内容没加载完时
  页面不够长，`scrollTo` 会被截断），再每帧把位置按回去，最多 4 秒；用户一动滚轮 / 触摸 /
  鼠标 / 键盘就立刻交还控制权。记录只存一条（`sessionStorage`，同标签页同源），十分钟内有效。
- 新增 `modules/returnRestore.ts`。

## 修复 · 悬停提示动画结束时的文字模糊

- 提示卡原来用 `translateY(-5px) scale(0.97)` → `translateY(0) scale(1)` 弹出来，动画刚停的
  那一瞬间文字是糊的。原因：设置面板整体是 `transform: scale(1.2)`，提示卡自己再挂一个
  `transform` 动画就会单独成层，Chrome 按动画起点的精度光栅化这一层、结束前不再重绘，
  文字就被父级那 1.2 倍放大着看。
- 改成**只位移不缩放**，并且悬停终态写 `transform: none` 而不是 `translateY(0)`：
  终态仍是 `transform` 的话元素会留在合成层里，要等下一次重新光栅化才清晰。
  `none` 才是「回到普通渲染」，动画结束的同一帧文字就是实的。
- 顺带把过冲曲线从 1.45 收到 1.32、时长 0.26s 收到 0.22s，纯平移下的回弹更克制。

## 内部优化（不影响观感与操作）

### 启动时只读一次存储

- 以前每个 store 各做一次 `chrome.storage.sync.get`、各挂一个 `onChanged`：十个数值参数
  store，加上开关、面板呼出键、轮盘、面板缩放、轮盘背景，**每次打开页面就是 15 次 IPC
  + 15 个监听**，而且各自的回调什么时候回来不确定（同一份配置可能被应用两次）。
- 现在新增 `contentScripts/storage.ts`：各 store 的 `bootstrap()` 退化成「登记 key + 怎么应用」，
  `index.ts` 里一次 `get(null)` 把整包读回来、只挂一个 `onChanged`，按 key 分发。
  两个带 epoch 记号的迁移（面板缩放刻度、轮盘背景参数模型）也因此不再需要「先写回、再重读」，
  换算完直接应用 —— 少一次往返。
- 没有扩展环境时（本地注入调试）走 localStorage，同样先拍一份整包快照再分发，语义一致。

### `<body>` 的类名只盯一个观察器

- `videoLayer` / `videoFullscreen` / `playerMode` 原来各挂一个
  `MutationObserver(body, { attributeFilter: ['class'] })`，B 站每次给 body 改类名
  （滚动锁、夜间、播放器状态都会动）三个回调依次跑一遍。现在合并到
  `modules/bodyClass.ts`，一个观察器分发给三个订阅者。
- 顺带把「网页全屏的 body 类名」抽到 `shared/bilibiliDom.ts`：`webscreen-fix` /
  `player-full-win` 原来在三个文件里各写一份，靠注释「三处必须一致」维持 —— 漏改一处的
  表现是「一个模块认得出全屏、另一个不认」，而且只在直播站出现。

### 无障碍与暴露面

- 三颗说明感叹号现在可以 **Tab 聚焦**：聚焦时提示卡同样弹出、圆圈有一圈焦点环，
  并带 `aria-label` —— 原来只做鼠标悬停，键盘和读屏用户拿不到那段说明。
- `web_accessible_resources` 的匹配范围从 `<all_urls>` 收窄到 B 站：写全站的话任何网站
  都能探测到这个资源、从而判断「用户装了本扩展」。
- 「减少动态效果」下，开关的**悬停**放缩也一并关掉（之前只关了切换那一下）。
- 删掉 `src/contentScripts/styles.css`：它只被 emit 成 `style.css` 挂进
  `web_accessible_resources`，从来没有真正注入过页面（里面的类名代码里一次都没用过）。

## 技术细节

- 新增 `modules/playerMode.ts`：屏幕模式判定 + 变化通知（`onPlayerScreenChange`）。
  观察器只盯 `data-screen` 一个属性名（subtree），body 的 class 不递归 ——
  B 站页面上 class 的变化极其频繁，混进同一个观察器等于给每次 class 变更都加一道回调。
- 设置面板里「呼出功能轮盘 / 卡片大小 / 预加载范围」三处说明，现在都收在感叹号的悬停提示里。
- 新增 `shared/messages.ts`：内容脚本 → 后台的消息名与载荷类型，两边引同一个常量。
