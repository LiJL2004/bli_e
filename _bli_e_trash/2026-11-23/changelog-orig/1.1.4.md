# 1.1.4

> 小版本：右下角那列「操作浮钮」（返回顶部 / 刷新 / 设置键）可以收起来了 ——
> **自动隐藏**、**自动隐藏时始终显示操作按钮**、**半隐藏**三条，合成一张小卡收在
> 「界面优化 → 操作浮钮」。默认全关，跟 1.1.3 之前一模一样。

## 新增 · 操作浮钮的收纳

- 这三条管的是**同一列按钮**：⚙ 设置键、返回顶部、刷新。它们分属两个模块、两个
  Shadow DOM，但收起时必须像一列一样整体动，所以新增 `modules/floatDock.ts` 统一管 ——
  两边只负责登记「我是设置键 / 我是操作键」，位移与透明度都从这里写。
- **自动隐藏**（`fabAutoHide`，默认关）：鼠标不靠近屏幕右边缘时，整列滑出屏幕；
  移到右边缘 20px 内滑回来。滑出延迟 100ms（只是路过右边缘去拖滚动条时不该弹出来）、
  收回延迟 600ms（从浮钮挪到旁边时留容错）。鼠标压在浮钮上时永不收回。
- **自动隐藏时始终显示操作按钮**（`fabKeepActions`，默认关，`under: fabAutoHide`）：
  收起时只收走设置键，返回顶部 / 刷新 留在原位 —— 滚到页面中部想随手点「返回顶部」时，
  不用再去蹭屏幕边缘。鼠标落在它们身上也不会把设置键拉出来（只贴边才会）。
- **半隐藏**（`fabHalfHide`，默认关）：平时只露出右半边并压暗到 60%，鼠标移上去完全展开。
- 两条互斥：后打开的那个赢，另一个自动关掉。判定写在 `floatDock.ts` 而不是面板里，
  这样无论从哪儿改（面板、恢复默认、将来的同步）都不会同时开着。
- 面板开着时暂停收纳：⚙ 滑走了、设置面板还杵在屏幕上会很怪。关掉面板 600ms 后按原状态收起。
- 尊重系统「减少动态效果」：位移直接到位，不做补间。

## 实现上的四个坑（都是实测出来的）

- **动的必须是影子根里那颗按钮，不能是宿主 div**。设置面板和 ⚙ 在同一个影子根里，
  宿主一旦有 `translate` / `transform`，面板的 `position: fixed` 就会改以宿主为参照系，
  整块面板会缩进 44×44 的角落里。
- **用 `translate` 而不是 `transform` 做位移**。⚙ 和浮键的悬停放大 / 按下挤压都写在
  `transform` 上（还带弹性曲线），行内再写 `transform` 会把它们整个盖掉。`translate`
  是独立属性，两者可以各动各的、也各走各的 `transition`。
- **半隐藏要把滚动条宽度减掉**。视口最右那十几像素是滚动条，不透明、也接不到鼠标事件，
  露在它后面等于没露 —— 不减的话 44px 的圆在 Windows 上只剩 7px 能看、能点。
  所以半隐藏的位移是 `calc(50% + 24px - 滚动条宽)`，滚动条宽只在画半隐藏时读一次
  `innerWidth - clientWidth`。
- **收起后宿主那个 44×44 的空框要让开**。它是 `pointer-events: auto` 的，按钮挪走以后
  空框还在原地替页面挡下一整块点不到的区域（实测点在空框上命中的是宿主自己）。
  现在收起 / 半隐藏时宿主 `pointer-events: none`、只让按钮自己收事件。
- 边缘热区用 `window` 的 `mousemove`（被动、`requestAnimationFrame` 合帧、只读 `clientX`、
  不读布局），不在右边缘放命中区 —— 那会盖住滚动条，拖不动滚动条比看不见浮钮严重得多。
  监听只在「自动隐藏」开着时挂。

## 修复 · 播放页 beta 打开后视频会「停顿重播」一次

- 根因不在播放器，在**动 DOM 的时机**：播放页是 SSR 出来的，Vue 起来后要把整棵
  `#mirror-vdcon` 接管一遍，B 站自己还有个「白屏检测」会在首屏反复检查这几个容器。
  在这段时间里把 UP 主卡片从右栏搬进左栏，B 站会当成异常把整棵子树重挂一遍 ——
  连带把已经初始化好的播放器销毁重建，表现就是视频刚打开停一下、从头重播。
- 实测：1.0s / 2.0s 时插入节点都会被重挂，2.5s 之后就不会。所以搬动改成
  **2.6s 之后 + 播放器已挂上**才做（`scheduleMove()`）；等待期间 UP 主卡片由 CSS 藏起来，
  左栏用一条等高的 `::after` 占位，搬过来时下面的简介 / 标签 / 评论不会跟着跳。
- 顺带修掉一个既有 bug：`document_start` 时 `<body>` 还不存在，`bodyClass.ts` 与
  `playerMode.ts` 直接 `observe(document.body)` 会抛「parameter 1 is not of type 'Node'」，
  这个异常会把调用方整段初始化打断 —— 于是「网页全屏时浮动键隐藏」这类依赖 body 类名的
  功能一直静默失效。现在统一走 `observeBody()`，等 body 解析出来再挂。

## 修复 · 缩放窗口后顶栏有概率变成一整条白

- 现象：切换窗口大小时，整条顶栏变成一块白（导航、搜索框、右侧图标全不见），页面其余部分
  完全正常。不是每次都能复现。
- 根因：首屏那条**白色骨架栏**（`#bili-elite-topbar-skeleton`，64px、只有 logo、
  z-index 1002）原来只靠 CSS 条件退场 —— `html:has(.left-entry__item)`，导航项一不在就
  重新露出来。而 B 站的顶栏导航是**按窗口宽度响应式重建**的（实测缩放时
  `.left-entry__item` 的数量在 10 → 8 → 10 之间跳），重建的那一帧里导航项可能是 0 个，
  骨架栏就重新盖到真顶栏上。
- 改成**一次性退场**：真顶栏的导航项第一次出现时给骨架栏打上
  `.bili-elite-skeleton-retired`（`retireSkeleton()`），之后无论顶栏怎么重建都不再露出。
  骨架栏本来就是填「0 → 第一条真实顶栏」那段空窗的，退场后没有再出场的场景。

## 修复 · 打开 / 刷新播放页后右栏跑到屏幕外（右侧没白边）

- 现象：打开或刷新视频页，右侧没有白边、内容贴着窗口边缘甚至跑到屏幕外；手动缩一下窗口、
  或者在设置里把「播放页beta」关掉再打开，白边就回来了 —— 但一刷新又坏。
- 根因：`measure()` 第一次是在 `document_start` 跑的，那时文档还是空的 —— B 站自己的 CSS
  （给 `<html>` 加 `overflow-y: scroll`）还没应用、内容也没渲染，**根本没有纵向滚动条**，
  `documentElement.clientWidth` 等于 `innerWidth`。等内容和样式都进来、滚动条一占位，
  clientWidth 就少了 17px，**而滚动条出现不会触发 `window` 的 resize 事件**，于是
  measure() 再也不会被叫起来，整行比视口宽 17px：右栏右边缘压到滚动条底下 / 跑出窗口。
  手动缩窗口（resize）或关掉再打开 beta（重跑 `start()` → `measure()`）都会重新算一遍，
  所以那两个动作「能修好」。
- 修法：新增 `watchViewport()` —— `ResizeObserver` 盯 `<html>` 的尺寸，宽度一变就重算
  （滚动条出现 / 消失、开发者工具停靠、缩放都能抓到）；只在**宽度**变化时重算，`<html>` 的
  高度会随内容不停长，按高度触发会把主线程吃掉。

## 变更 · 播放页 beta：经典版信息区（对齐参考稿）

参考稿（YouTube 式）：标题 + 蓝色 `#话题` → 作者行 + 右侧操作栏 → 一张灰底卡片装「播放数据 + 简介」。

- **播放数据进简介卡**：播放量 / 弹幕数 / 发布时间原来是标题下面独立的一行，现在和简介合成
  一张浅灰卡片（`--graph_bg_thin`，圆角 12）。**这一步没有搬 DOM**：`#viewbox_report` 改成
  `display: contents`，里面的 `.video-info-title` / `.video-info-meta` 就直接成了左栏栅格的
  item，把 meta 也放进简介卡那一行、靠 z-index 压在卡片顶部那块留白里（卡片 `padding-top: 44`
  = 12 + 24 + 8）。为什么不学 UP 主卡片那样真搬：简介是 Vue 高频重渲染的区域（展开 / 收起、
  换 P、字幕作者列表后到），往 `#v_desc` 的 children 里插节点会让 Vue 的「按索引 patch」错位。
  图标顺手从 20px 收到 16px、字收到 12px（卡片里空间紧，参考稿的播放数据也是小一号的）。
- **标签变成标题后面的话题链接**：原来简介下面那排灰色胶囊（`.video-tag-container`）整条隐藏，
  标签由 `decorateTags()` **克隆**成 `#标签` 链接接到标题后面（蓝色 `#065FD4`，字号跟标题一致
  20px/500）。克隆而不是搬：`.tag-panel` 是 Vue 渲染的，搬走的节点下次重排就会被挪回去或者
  变成孤儿；克隆不在 vnode 树里，标签内容一变（`data-sig` 比对）就整串重建。
  标题因此改成行内流（`display: inline`，去掉两行 `-webkit-line-clamp`），长标题 + 一串话题
  能自然折行 —— 参考稿就是一行读完。
- **操作栏下移到作者行右边**：点赞 / 投币 / 收藏 / 分享原来在标题右边（第 2 行第 2 列），
  现在和 UP 主那一行同一行（第 3 行第 2 列、垂直居中）。标题独占整行，宽出来的一截正好给
  长标题和话题链接。**操作栏底下那条 1px 灰线一起去掉**（`border-bottom: none`，
  连同 `padding: 16px 0 12px` 收成 0，不然会悬一条孤线在那儿）。
- 窗口窄于 1120px 时操作栏退回单独一行（原来的上下结构），后面的块整体下移一行。

## 播放页 beta：加载期 UP 主控件被滚轮带走 + 信息区收紧（v019）

### UP 主控件在「还没加载完」时钉不住

三个原因叠在一起，都修了：

1. **B 站是「第一次滚动时才写行内 top」的**。在那之前左栏根本没有 sticky top（计算值 `auto`），
   我们的卡片跟着 `top: auto` 一起不钉 —— 一滚就整块滑走。现在 `videoBeta.ts` 按 B 站同一个公式
   （`min(视口高 − 左栏高, 顶栏高)`）算一个**兜底值**写进 `--bili-vb-left-top`，CSS 里
   `.left-container { top: var(--bili-vb-left-top, auto) }`。**不加 `!important`**：行内样式优先级更高，
   B 站一写就自然接管，两边不会打架。
2. **几何变了但没人重算**。`layoutUp()` 原来只在 childList 变动时跑；播放器挂上（`#playerWrap`
   从 0 长到 16:9）、标题折行、评论加载都只是**尺寸**变化，一条 mutation 都没有。于是标题被顶下去

   现在用 `ResizeObserver` 盯 `#playerWrap` / `.video-info-title` / `.left-container`，回调甩到下一帧
   再 `layoutUp()`（避免 `ResizeObserver loop` 警告）。
3. **卡片宽度可能被写成 0**。`layoutUp()` 原来用「卡片宽度为 0」判断「面板还没渲染」——首帧左栏
   还没排版时量到 `grid-template-columns` 是 `0px`，写进 `--bili-vb-up-w` 之后卡片宽度变 0，
   于是永远走那个提前返回、宽度再也修不回来（窄窗口实测卡片整个消失）。现在只写正数宽度，
   「渲染了没」改用高度判断。

顺带修了窄窗口（≤1120）的兜底规则：v017 给基础规则加了 `:not(.bili-elite-vb-immersive)`，

（窄窗口下标签直接看不见）。现在放开高度与裁切，meta 跟着长高，卡片的上内边距照旧由
`--bili-vb-desc-top` 追。

## 播放页 beta：刚打开网页时控件挤在一起（v020）

截图里是标题被 UP 主那一行压住了。查下来是**首屏那几百毫秒**里两件事叠在一起：

1. **左栏还不是 sticky，我们却给它写了 `top`**。B 站是后挂 `.scroll-sticky` 的，在那之前左栏是
   `position: relative` —— 这时 `top` 会被当成**相对偏移**，把整栏往上或往下推几十像素
   （实测首屏 300ms 时顶栏还渲染成 91px 的「大 banner」，我们按它夹出一个 `top: 91px`，
   左栏被推下去 27px；之后顶栏收成 64，又变成推上去 24px）。卡片是按右栏算位置的，跟不上，
   于是标题和 UP 主那一行就叠在一起。
   → `syncLeftTop()` 现在**先看 `position`，不是 sticky 就不写**（并把旧值撤掉）；
   顶栏高度也夹在 64 以内（首屏那个 91px 是临时的）。观察器顺带盯 `class`，
   B 站加/摘 `.scroll-sticky` 都会立刻重算。
2. **位置还没量出来卡片就画出来了**。标题没排版时 `--bili-vb-up-y` 要么没有（卡片贴在右栏最上面）、
   要么按 0 高的标题算（卡片正好压在标题上）。
   → 新增 `html.bili-elite-vb-up-ready`（由 `layoutUp()` 量出位置后挂上），之前卡片 `visibility: hidden`
   （不是 `display: none`，占位还在、左栏行高不会跳）。另有 2s 兜底：万一标题一直不出现，
   到点也让卡片现身，不会永远藏着。

## 修复 · 简介卡：B 站原版的「展开更多 / 收起」回来了（v025）

v018 做简介收起时，用 `max-height` 把正文压到 2 行，又自己用 `::after` 画了一颗居中的「收起」。
两个问题，根子在同一个地方：

- **B 站的折叠判定被我们骗了**。它 `checkIfDescInfoCanBeFolded` 量的是
  `getBoundingClientRect().height`：正文被压成 52px 之后 `52 > 3.5 × 行高` 不成立，
  于是它判定「这篇简介不需要折叠」，`#v_desc` 末尾那颗原版 `.toggle-btn`
  （简介左下角的「展开更多」）直接不渲染 —— 看起来就像被我们删了。
- **自己画的收起按钮是多余的**。原版按钮一直都在，而且「展开更多 ↔ 收起」就是同一个节点。

现在：

- 高度、阈值（B 站是 3.5 行）、按钮**全部交回 B 站**，`videoBeta.css` 里不再有任何
  `max-height` / `height` 覆盖。
- 只留两件「加料」：收起态整张灰卡 `cursor: pointer` + 悬停高亮
  （`html.bili-elite-vb-desc-folded`，由 `syncDesc()` 读 B 站自己的行内 `height` 挂 ——
  收起时它写死 px、展开时写 `auto`）；点灰卡任意位置 = 展开。
- 点灰卡走的是 `btn.click()`，也就是**直接点 B 站那颗按钮**：折叠状态、行内高度、按钮文案
  都由 B 站维护，我们一个字节都不写。点链接 / 图片 / 按钮自己、以及正在拖选文字时放过。
- 没有简介的稿件（`bili-elite-vb-nodesc`）照旧强制画出灰卡 + `~` 占位，这条没动。

## 修复 · 带头像框的 UP 主信息间距过大 / 已关注按钮上残留粉丝数（v026）

两件事，根因不一样：

- **间距**：带头像框（B 站叫「挂件」）的 UP 主，B 站把 `.up-avatar-wrap` 撑到 **80×80**、
  头像本身缩到 85%（行内 `width:40.8px` + `translate(3.6px)`），再叠一张 72×72 的挂件图。
  于是这一行从 48 高变成 80 高 —— 标题下那 8px 没变，是卡片自己胖了 32px，把简介卡
  往下推、左栏第 3 行的占位也跟着长，看起来就是「这个 UP 主的控件间距特别大」。
  现在挂件直接不显示，wrap / 头像 / 内层三层尺寸按「无挂件」的原样钉回 48（实测无挂件的稿件三层都是 48、translate 0）。
  纯 CSS，**不删节点**：`.has-pendant` 是 Vue 的 class，摘 DOM 会踩它的 patch。
- **粉丝数**：B 站把关注按钮的文案改成了
  `<span class="follow-btn-inner"><span class="already-btn"><svg/>已关注 126.8万</span></span>`
  —— 比原来多包了一层 `.already-btn`。我们之前按「直接子节点里的最后一个文本节点」
  去拆「已关注」和粉丝数，于是「已关注」态一个都拆不到（未关注态还是老结构，所以只有已关注的
  UP 主会露馅）。现在改成递归找（跳过「设置分组 / 取消关注」那个悬停浮层），两种结构都能拆，
  按钮上只剩「已关注」（带图标），粉丝数照旧在名字下面那一行。

## 修复 · 充电按钮的占位和实际尺寸不一致（v027）

`upinfo-btn-panel` 里的充电按钮有**两套实现**：新的 `.new-charge-btn`、经典的 `.old-charge-btn`

## 技术细节

- 新增 `modules/floatDock.ts`：`registerFloatDock({ role, host, animEl, hoverEls })` +
  `setFloatDockPaused()`。两颗浮钮先后登记（⚙ 在首屏、浮键在空闲时），登记后立刻按当前
  开关画一次，所以不会出现「⚙ 收起了、浮键还露着」的错位。
- 位移量在登记时读一次宿主的 `right`（24px）存起来，之后不再读布局；
  收起 = `calc(100% + gap + 8px)`，半隐藏 = `calc(50% + gap - 滚动条宽)`。
- 播放页 beta 的两处跨容器搬动（UP 主卡 / 弹幕发送栏）都在 `scheduleMove()` 的水合窗口之后才做；

  晚一拍解析出来，`bindObservers()` 那时已经返回了，得在这里补绑；UP 主骨架的
  `up-pending` class 也在这里跟着「面板在不在 / 搬没搬」切换。
- 开发版本：`1.1.4 v020`。

## 修复 · 发送弹幕控件和原版不一致（v028）

对照用户给的原版截图（网页全屏的控制栏）：中间那条 729×34，输入条 645×34、8px 圆角、
`rgba(255,255,255,.3)` 底、右端「弹幕礼仪 >」+ 64×34 蓝底发送键（`#00aeec`）。两头都不对：

- **网页全屏 / 全屏被压扁**：发送栏那几条规则（28px 高、最宽 420、藏弹幕礼仪、14px 胶囊圆角）
  没带 `:not()`，全屏也被套上了 —— 条子 28 高、发送键 34 高（B 站写死 `min-width: 62`，
  压不住），键上下都露在条子外面，弹幕礼仪也没了。现在新增 `bili-elite-vb-send-native`
  （`playerMode.ts` 的 `isPlayerFullscreen()`，只有网页全屏 / 全屏才挂）：这两态一条规则都不写，
  整块交回 B 站，实测就是原版那组数字（729 / 645 / 64 / 72 / 34）。
  **宽屏不算**：宽屏下 B 站仍把发送栏挂在播放器下面那 56px 里，我们搬进控制栏之后必须套窗口态
  那套深色皮肤 —— 否则会露出浅色的原版皮肤（白底、输入条 `#f1f2f3`）。
- **窗口态不居中**：控制栏是「左组 + 中间 + 右组」的 flex，左 136、右 388，中间那块因此
  天然偏左 126px，发送条跟着偏。现在三块都改成 `flex: 1 1 0`（`min-width` 留 auto）：
  宽窗口下各占 1/3，中间那块正好落在播放器中线（2560 窗口实测 `barCenter − playerCenter = 0`）；
  窗口一窄，左右两块按自己的内容撑住、中间跟着缩，永远盖不到按钮上（1200 窗口实测条子
  208 宽、两侧按钮原位不动）。
- **窗口态外观照抄原版**：30px 高（控制栏只有 35px，原版 34 会顶满）、最宽 560、发送键 56×30，
  圆角 8px、0.3 白底、弹幕礼仪留着（`@container` 判条子自己的宽度，窄到 380px 以下才让出去）。

  发送键的蓝底在子节点 `.bui-area.bui-button-blue` 上，圆角要一起改。


## 变更 · 播放页左栏的「活动推广」横幅不再显示（v030）

  这个容器还可能装稿件自带的资源（素材 / 下载），那是真内容，得留着。所以规则只命中
